# 정적 웹 사양 복원 분석 보고서

작성일: 2026-11-02

> 이 보고서는 구현 전 Python/웹 비교 기록입니다. 이후 모델·발음·CTC·HuBERT·WORLD·가져오기 경로가 구현되어 이 문서의 “현재 웹” 표는 최신 상태가 아닙니다. 최신 구현과 검증 결과는 [정적 웹 앱 안내](static-web.md)를 참조하세요.

## 목적과 분석 범위

서버 없는 정적 웹 배포를 유지하면서 기존 Python 구현의 인식·음소 타이밍 정확도와 피치 편집·합성 음질에 최대한 가까워지는 경로를 분석한다. 두 영역 모두 필수 목표다.

기준은 `legacy/python` 브랜치와 현재 작업 트리의 웹 소스다. 소스 비교 보고서이며, 모델 다운로드·ONNX 변환·WASM 빌드·실제 음성 비교·성능 측정은 수행하지 않았다. 아래 이식 경로는 기술 제안이며 실행 가능성이 검증된 구현으로 해석하면 안 된다. 기존 작업 트리 변경은 유지했다.

## 결론

현재 웹은 Python 실행 환경만 바꾼 구현이 아니다. ASR 모델, 발음 변환, 음소 정렬, 음향 임베딩, 피치 분석·합성 알고리즘에 차이가 있다. 큰 Whisper 모델을 추가하는 작업만으로는 기존 사양에 근접하지 못한다.

정적 배포 자체는 대형 모델이나 CTC·HuBERT·WORLD를 배제하는 근거가 아니다. 다만 네이티브 추론 엔진과 Python 확장 모듈을 그대로 브라우저에서 실행할 수는 없다. 모델의 브라우저 지원 형식 변환과 WORLD의 WASM 컴파일을 별도로 검증해야 한다. 동일 모델·알고리즘을 사용해도 수치 정밀도, 전처리, 디코딩 차이 때문에 결과의 완전 일치를 보장할 수 없다.

## A. 인식·음소 타이밍 정확도

### 확인한 차이

| 항목 | 기존 Python | 현재 웹 | 영향 |
| --- | --- | --- | --- |
| 기본 ASR | `large-v3` | `Xenova/whisper-tiny` | 모델 용량과 인식 특성이 다름 |
| 주요 선택지 | large-v3 / large-v3-turbo / small | tiny / base / small | 기존 주요 모델 선택 불가 |
| 추론 | OpenVINO / faster-whisper 등 | Transformers.js / ONNX Runtime Web | 엔진·정밀도·생성 옵션 차이 |
| 웹 정밀도 | 해당 없음 | WebGPU fp32, WASM q8 | 대형 모델에 그대로 적용할 정책인지 검증 필요 |
| 발음 변환 | g2pk / g2p-en / pykakasi | 간이 규칙·소규모 사전 | 정렬 대상 음소와 검색 결과가 달라질 수 있음 |
| 음소 정렬 | wav2vec2 CTC | 단어 시간·에너지 기반 추정 | 음소 경계의 근거가 다름 |
| 음향 단위 | HuBERT 768차원 임베딩 | 직접 계산한 음향 특징 | 반복 음향의 유사도 공간이 다름 |

Python 기본 정렬은 `ctc`, 음향 단위 분석은 활성화다. CTC 모델은 `facebook/wav2vec2-xlsr-53-espeak-cv-ft`, HuBERT는 `facebook/hubert-base-ls960`이다.

현재 웹 worker는 ASR 반환 chunk에 여러 단어가 있으면 시간을 균등 분할한다. timestamp chunk가 없을 때도 전체 구간에 단어를 균등 배치한다. 이후 음소는 `ESTIMATED_WORD`, `LOW_CONFIDENCE`로 기록된다. ASR 모델만 교체해도 이 시간 추정은 남는다.

발음 변환도 독립적인 복원 대상이다. 한국어는 일부 연음·비음화 규칙, 영어는 작은 사전과 철자 규칙, 일본어는 가나 표와 제한된 한자 사전에 의존한다. 기존 발음기의 사전·문맥 처리와 동등하지 않다.

### 권장 이식 경로

1. **Whisper 모델과 생성 동작 복원:** large-v3 및 large-v3-turbo의 호환 ONNX 아티팩트, tokenizer, 전처리, 단어 timestamp 지원을 확인한다. 이름만 같은 모델을 연결하지 말고 원본 체크포인트와 변환·양자화 정보를 기록한다.
2. **추론 정책 명시:** GPU용 정밀도와 WASM용 정밀도를 따로 검증한다. 메모리 부족 시 작은 모델로 자동 교체하지 않고 선택 모델의 실패 원인을 표시한다. turbo는 large-v3와 별도 선택지로 취급한다.
3. **CTC 복원:** 기존 체크포인트의 logits를 브라우저에서 얻고, 기존 IPA 토큰화·정규화·패딩·CTC 동적 계획법·confidence 판정을 이식한다. 단순한 범용 강제 정렬 라이브러리로 교체하는 방식은 동등성을 보장하지 않는다.
4. **발음기 복원:** 기존 사전·모델·규칙을 확보하고 브라우저 이식 또는 WASM 실행 가능성을 조사한다. 사전 배포 크기와 라이선스도 확인해야 한다.
5. **HuBERT 복원:** 같은 hidden output을 추출하고 기존 구간별 평균, 64개 이하 클러스터, 초기화·반복·저장 순서를 유지한다.

### 제약과 미확인 사항

- 대형 모델의 실제 다운로드 크기, 최대 GPU 버퍼, GPU 메모리, 모델 로딩 중 복제 메모리는 미측정이다. 저장 파일 크기만으로 실행 메모리를 판단할 수 없다.
- ONNX 연산자와 WebGPU 실행 지원, 단어 timestamp의 attention 출력 요구, 변환 모델의 품질은 아티팩트별 검증이 필요하다.
- 현재 WASM은 한 스레드로 설정되어 있다. 대형 모델 CPU 실행의 실용적인 속도는 확인하지 않았다.
- Whisper의 chunk overlap, 문맥 전달, VAD, 언어·생성 옵션도 기준 엔진과 맞춰야 한다. 모델 크기 일치만으로 transcript 일치가 성립하지 않는다.
- CTC·HuBERT·Whisper는 순차 로딩과 명시적인 자원 해제를 우선 검토한다. 모든 모델을 동시에 상주시킬 필요는 없다.

### 비교 검증안

| 대상 | 측정 항목 |
| --- | --- |
| 전처리 | 같은 입력에서 PCM 샘플레이트·모노 변환·파형 차이 |
| 발음 변환 | 한국어·영어·일본어의 IPA 및 phone ID 일치율 |
| ASR | 사람이 검수한 정답 대비 CER/WER, 기준 Python 대비 차이 |
| 음소 정렬 | 정답 경계 대비 시작·끝 오차의 중앙값·상위 백분위, 누락·저신뢰율 |
| HuBERT | 동일 구간 임베딩 차이, 같은 음향 검색·군집의 일관성 |
| 운영성 | 초기 다운로드·로딩 시간, 처리 시간/입력 길이, 메모리, 반복 실행·취소 후 자원 회수 |

Python 결과와의 일치는 동등성 지표이고, 사람 정답 대비 정확도와는 구분한다. 허용 오차는 기준 자료의 측정 후 합의해야 하며 현재 보고서에서 임의로 확정하지 않는다.

## B. 피치 편집·합성 음질

### 확인한 차이

기존 전문 합성의 `world_pitch.py` 경로는 16 kHz 모노 입력, 앞뒤 120 ms 문맥, 5 ms 프레임을 사용한다.

`DIO → StoneMask → CheapTrick → D4C → 시간 매핑·F0 편집 → WORLD synthesize`

F0뿐 아니라 spectral envelope와 aperiodicity도 분석한다. 출력 시간에서 원본 시간으로 매핑한 뒤 spectrum과 aperiodicity를 보간하고, 유성 프레임에 음정·엔벌로프·비브라토·피아노 노트를 적용한다. 편집이 없으면 원본 구간을 반환하는 경로와 0.98 peak 제한이 있다.

현재 `audioDsp.ts`는 자기상관으로 F0를 추정하고, 선형 리샘플링과 overlap-add 시간 늘이기로 피치를 변경한다. 곡선은 각 프레임의 평균 cents로 처리하며, 별도 FFT 기반 포먼트 보정을 사용한다. WORLD의 spectrum·aperiodicity 분석 및 재합성 경로가 아니다.

이는 음질 차이가 발생할 구조적 이유다. 실제 열화 정도나 어느 입력에서 더 나쁜지는 청취·측정 전에는 확정할 수 없다. 또한 기존 Python에도 자기상관·시간 늘이기 코드가 있으므로 모든 Python 기능이 WORLD였다고 해석하면 안 된다. 복원 시 호출 경로별 기준을 구분해야 한다.

### 권장 이식 경로

**기존 PyWORLD가 호출하는 WORLD C/C++ 코어를 WASM으로 빌드하고 기존 편집 로직을 함께 이식하는 경로**를 우선 검증한다. JavaScript로 비슷한 보코더를 새로 구현하는 것보다 알고리즘 일치를 유지하기에 적합하다.

유지할 사양:

- DIO·StoneMask·CheapTrick·D4C·Synthesis의 버전과 옵션
- 16 kHz 입력, Float64 분석, 5 ms 프레임, 120 ms 문맥
- 원본/출력 시간 매핑, 최근접 F0 선택과 행렬 보간
- 무성 구간 처리, 편집 우선순위, 비브라토와 노트 적용
- 무편집 원본 반환, 출력 샘플 수 보정, peak 제한
- 기존 오토튠·일반 피치 변환 등 다른 호출 경로의 동작

Worker에서 분석·합성하고 모델 추론과 큰 메모리 점유가 겹치지 않게 한다. WASM 내 spectrum·aperiodicity는 가능한 한 유지해 JavaScript 왕복 복사를 줄인다. 구간 처리는 기존 문맥과 경계 처리를 유지한 상태에서 검증한다.

### 메모리와 정적 배포 제약

WORLD는 신경망 모델 다운로드 대신 분석 행렬 메모리가 중요하다. 두 행렬만의 메모리는 대략 `프레임 수 × 주파수 bin 수 × 8 bytes × 2`다.

예를 들어 5 ms 프레임, 513 bins를 가정하면 1분의 spectrum·aperiodicity만 약 98.5 MB다. 이는 실제 FFT 크기를 측정한 값이 아니며 입력·출력·임시 배열·복사 메모리를 제외한 예시다. 긴 전체 파일을 한 번에 분석하는 설계는 피해야 한다.

단일 스레드 WASM으로도 검증 경로를 설계할 수 있으나 처리 속도는 미확인이다. SIMD 및 멀티스레드 최적화는 별도이며, SharedArrayBuffer를 사용하는 일반적인 멀티스레드 구성에는 cross-origin isolation 조건이 따른다. 현재 Pages 배포의 헤더 조건에 의존하지 않는 기본 경로가 필요하다.

빌드 도구, WORLD 소스 확보, 사용 버전·라이선스, 브라우저별 WASM 실행 결과는 아직 확인하지 않았다.

### 비교 검증안

| 대상 | 측정 항목 |
| --- | --- |
| 분석 동등성 | 같은 PCM에서 F0, 유성/무성, spectrum, aperiodicity 차이 |
| 무편집 출력 | 선택한 원본 구간과 샘플·길이 일치 |
| 편집 출력 | 출력 길이, 목표 피치 오차, peak·NaN·클리핑 |
| 음질 | 자음 보존, 무성음, 배음, 포먼트, 연결부 클릭·버징에 대한 블라인드 A/B 청취 |
| 복합 편집 | 시간 늘이기와 피치 곡선·비브라토·노트가 겹치는 경우 |
| 운영성 | 짧은 음소·여러 구간·긴 작업의 최대 메모리·취소·반복 실행 |

±25/100 cents 등 작은 변화와 옥타브 변화, 저음·고음, 숨소리·무성 자음, 구간 경계를 포함한다. 평균 피치나 사인파 테스트만으로 합성 품질을 판정하지 않는다. 동일 알고리즘이라도 완전한 파형 일치는 별도 검증 대상이다.

## 공통 선행 조건과 진행 순서

1. 기준 Python의 실행 버전·모델 revision·설정과 비교용 PCM/정답/출력을 고정한다. 프로젝트 의존성 범위만으로 과거 실행 바이너리의 정확한 버전을 알 수는 없다.
2. 두 개의 작은 검증을 각각 수행한다: 대형 Whisper+CTC의 짧은 입력 추론, WORLD WASM의 분석·합성. 한쪽 성공을 다른 쪽 품질 충족으로 간주하지 않는다.
3. 두 경로의 결과·시간·메모리를 측정한 뒤 발음기·HuBERT·전체 편집 흐름으로 확장한다.
4. 전처리와 저장 형식·분석 버전 관리를 맞춰 같은 프로젝트로 비교할 수 있게 한다. SQLite와 centroid 파일 호환성도 별도 작업이다.
5. 품질 기준을 통과한 뒤 모델 캐시·분할 처리·GPU 정밀도 등을 최적화한다. 축소 모델이나 간이 DSP로 자동 대체하지 않는다.

현재 단계에서 개발 기간, 권장 RAM/VRAM, 처리 속도, 수치 허용 오차를 확정할 근거는 없다. 첫 검증의 산출물은 지원 모델/연산자 목록, WORLD 빌드 재현 절차, 동일 입력 비교 결과, 실패 환경과 메모리 측정값이어야 한다.
